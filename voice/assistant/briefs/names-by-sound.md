# Brief: names-by-sound — find a stock whose name speech recognition wrote as a homophone

## Why
XiaoAi's speech recognition often writes a name with other characters of the same sound. On the TV on 2026-11-07 the user
said 「查询智谱和MINIMAX股价并且进行比较」 and 星仪 received 「查询质朴和MINIMAX股价…」. `stock_quote` searched Tencent's name
search for 「质朴」, got nothing (`v_hint="N";`) and 星仪 asked the user what 「质朴」 was; the user had to try three more
times. Tencent's search takes pinyin: `zhipu` and `zp` both return 智谱 (hk02513) first. So when a Chinese name is not
found, 星仪 should search again by how it sounds, accept only a stock whose name really sounds like what was heard, and
say what it did: 「「质朴」按读音查的是智谱：智谱 426.20 港元，跌 10.46%（11 月 6 日收盘）」.

## What to build

### 1. `tests/agent/pinyin_gen.py` → `src/xyz/erapi0neer/xingyi/agent/PinyinData.java`
`pypinyin` 0.55.0 is installed for `python` on this machine (do not install anything). The generator:
- enumerates the 6763 Chinese characters of GB2312: for `hi` in 0xB0..0xF7 and `lo` in 0xA1..0xFE,
  `bytes([hi, lo]).decode("gb2312")`, skipping the byte pairs that fail to decode;
- for each character takes `pypinyin.pinyin(ch, style=pypinyin.Style.NORMAL, heteronym=True)[0]` (toneless, most common
  reading first, `ü` written `v`: 绿 → lv, lu), lower case, duplicates removed in order;
- writes `PinyinData.java`: package `xyz.erapi0neer.xingyi.agent`, `final class PinyinData`, a header comment
  `// Generated by tests/agent/pinyin_gen.py from pypinyin <version>: GB2312's 6763 characters. Do not edit.`, and
  `static final String[] CHUNKS` — entries `<character><reading>[,<reading>…];` in code-point order, at most 1500
  entries per chunk (a Java string constant must stay under 65535 bytes of modified UTF-8; a Chinese character takes 3);
- writes the file with `newline="\n"` and UTF-8;
- `python tests/agent/pinyin_gen.py --check` regenerates in memory, compares with the file on disk and prints
  `PINYIN DATA OK` (exit 0) or `PINYIN DATA STALE` (exit 1).

### 2. `src/xyz/erapi0neer/xingyi/agent/Pinyin.java` (pure: java.util only, no android.*, no org.json needed)
```java
public final class Pinyin {
    /** Every reading of a Chinese character, toneless, lower case, most common first (「朴」→ pu, piao, po); empty for anything else. */
    public static List<String> readings(char c)
    /** Whether the text has a character that has readings. */
    public static boolean hasChinese(String s)
    /** What a pinyin search is given: each Chinese character's first reading, ASCII letters and digits in lower case,
     * everything else (spaces, punctuation, other scripts, characters without readings) left out.
     * 「质朴」→ "zhipu", 「MINI MAX」→ "minimax", 「B站」→ "bzhan". null → "". */
    public static String spell(String s)
    /** The first letters of the same: 「质朴」→ "zp", 「贵州茅台」→ "gzmt", 「B站」→ "bz". null → "". */
    public static String initials(String s)
    /** Same sound: keep the characters spell() keeps; the same number of them; at each position two Chinese characters
     * share at least one reading, anything else is equal ignoring case. 「质朴」/「智谱」 yes, 「支付」/「智谱」 no,
     * 「银行」/「银杭」 yes (行 has hang), 「毛台」/「茅台」 yes, 「质朴」/「智谱AI」 no (lengths differ). */
    public static boolean sameSound(String a, String b)
    /** Where in b a stretch sounds like a (same rule, a stretch of b's kept characters as long as a's): the index of its
     * first kept character, -1 when there is none. 「毛台」 in 「贵州茅台」 → 2; 「质朴」 in 「智谱」 → 0. */
    public static int soundIndex(String a, String b)
}
```
Parse `PinyinData.CHUNKS` lazily once (first call) into a `HashMap<Character, String[]>`; thread-safe (a `synchronized`
init or a holder class). Never throw on null or odd input.

### 3. `Quotes.java`: `Hit` and `bySound`
```java
/** A search result found by how its name sounds. */
public static final class Hit {
    public final String code, name;   // code as qtCode gives it ("hk02513"), name as the search wrote it ("智谱")
}
/** The stock or index in a search answer (the answer for spell(query) or initials(query)) whose name sounds like the
 * query, or null. Rank: the bare name (SUFFIX removed, as in pick) has the same sound as the query → best; it starts with
 * a stretch of that sound → next; it has one inside → last; a name with no such stretch is never taken. Within a rank the
 * order and the exclusions are exactly pick's (stock before index unless the query has 指数; A shares, then Hong Kong,
 * then the US; funds, ETFs, warrants, leveraged/inverse products, US OTC and the RMB counter skipped). */
public static Hit bySound(String searchText, String query)
```
Share the search-answer parsing with `pick` (one private helper that unescapes `\uXXXX` and splits the items);
`pick`'s results must not change (the existing FeedChecks prove it).

### 4. `TvTools.java`, the `stock_quote` tool only
Today, when `Quotes.pick(...)` returns null for a part, the tool fails with `not_found`. Change only that: when the part
`Pinyin.hasChinese(part)`, search again with `Pinyin.spell(part)`, then (if still nothing) with `Pinyin.initials(part)`
(skip an empty or repeated spelling), each through the same `NAME_FEED.get(Quotes.SEARCH + spelling, "UTF-8", 6000)`,
and take `Quotes.bySound(answer, part)`. Found → use its code and remember `「<part>」按读音查的是<name>`. Not found →
the same `not_found` as now, with 「（按读音 <spell> 也没找到）」 added before the colon. When anything was found by sound:
the spoken `answer` becomes `<the remembered phrases joined by "；">：<answer as now>`, and the result gets
`"heard_as": [{"said": "质朴", "found": "智谱", "code": "hk02513"}]`. Nothing else in TvTools changes.

## Examples (real data in the fixtures)
- `bySound(smartbox-zhipu, "质朴")` → hk02513 / 智谱 (the 智谱… warrants after it are type QZ: skipped).
- `bySound(smartbox-zp, "质朴")` → hk02513 / 智谱 (中盘高贝 etc. do not sound like 质朴).
- `bySound(smartbox-maotai, "毛台")` → sh600519 / 贵州茅台 (contains a stretch that sounds like 毛台).
- `bySound(smartbox-zhifu, "质朴")` → null (智富, 置富产业信托 do not sound like 质朴).
- `bySound(smartbox-zhipu-misheard, "质朴")` → null (`v_hint="N";`).
- `pick(smartbox-zhipu-hanzi, "智谱")` → hk02513 (unchanged behaviour).

## Common mistakes to avoid
- Accepting the first item of the pinyin search without the sound check: `zp` also returns 中盘高贝, 展鹏科技…
- Comparing only the first reading: 「朴」 in 质朴 is pu, but its first reading is not what decides; any shared reading counts.
- Counting spaces, 「·」 or the `-W`/`w` share-class marks as characters (SUFFIX removes them before comparing).
- Building the Java data file with a shell heredoc (backslashes collapse) — the generator writes it.
