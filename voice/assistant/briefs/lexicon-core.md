# Brief: 常提到的名字 —— `Lexicon`：从对话里学会用户常说的名字，和识别把它们写成过什么

## 背景（真实发生的事）

用户 2026-11-19：「记忆归纳整理系统也需要优化，以及偏好习惯，比如经常理解 tibo，而不是让我读 T I B O」。

电视上用了 30 天、190 句话，记忆里只有 4 条事实、1 条名字写法、4 行按次数数出来的习惯，没有用户问得最多的
Tibo、MiniMax、OpenAI、智谱。11-06 00:04 用户说「看一下 Tibo 的推特」，识别三次写成「TABLE」，星仪反问
「TABLE 指的是哪个」，用户一个字母一个字母说「TI BO 这个人」才认出来；第二天又被写成「TIBA」。
现有的 `Heard`（`src/xyz/erapi0neer/xingyi/agent/Heard.java`）每次请求把 30 天历史重看一遍，只认两种严格的形状
（是长名字的一截、只差一个字母），什么都不记，所以同一次返工下周还要再付一遍。

你要实现的是 `src/xyz/erapi0neer/xingyi/agent/Lexicon.java`。**它的 API 和每个方法的契约已经写在这个文件里
（主控写的桩），先读它。** 纯逻辑：没有 android.*，不联网，不读写文件（电视那边只负责把 JSONObject 读进来、存回去，
那是下一单的事）。

## 考卷

`tests/agent/LexiconOracleChecks.java` 是主控写的考卷，240 条检查，**你不能改它**（也不能改它读的
`tests/agent/fixtures/history-2026-11-07.json`）。把 `Lexicon.IMPLEMENTED` 改成 `true` 它才会跑。它分两半：

1. 把电视上 11-05 到 11-07 的 86 句真实对话按时间重放给 `Lexicon.learn`，然后要求：`TABLE`、`TIBA`、`提博`、
   `T I B O` 都被提示成 `Tibo`；`MAX` 是 MiniMax；`质朴`、`制储` 是 `智谱`；`OPEN A` 是 OpenAI；这 86 句里别的词
   一个都不许乱提示；20 句日常的话不许有提示；「关于用户」的几行里有这四个名字、没有只在回答里出现过的名字。
2. 同样形状、换了名字的几段编出来的对话（ANTROPIC / Anthropic、CLOUD / Claude、VIDIA / NVIDIA、必亚迪 / 比亚迪），
   以及不该连在一起的情况、上限、坏输入。这一半是为了让第一半不能靠「认得那几个字符串」通过。

**`Lexicon*.java` 的代码里不许出现考卷里的任何一个名字或错写法**（注释里讲故事可以）；验收脚本会查。
规则要讲得出道理，下面给了每条规则的来历。

## 规则（每条都对应上面记录里的一件事）

**一个回合「听懂了」还是「没听懂」**（`Turn.state` 有就用，没有就看回答；那 86 句的 fixture 里 state 都是空的）：
- 没听懂：`cancelled`（或回答就是「已停止。」）、`awaiting_user`、`failed`；或者回答**在问用户指的是什么**。
  判断「在问」要先用 `Speech.settled(replied)` 去掉结尾的提议（「要我去看他的主页动态吗？」是提议，不是没听懂——
  11-06 认出 Tibo 的那一句正好以这种提议结尾），去掉以后还剩问句才算。
- 没听懂的回合**不产生名字**：回答里引号括着的词（「“质朴”是指哪只股票？」「TABLE 指的是哪个？」）是把用户的话
  念回去，不是名字。它留下的是「一个没着落的词」，等后面的回合来认领。

**名字从哪来**（只在听懂了的回合）：
- `Turn.names`（工具真正操作的对象，写法是对的；电视上有，fixture 里是空的）；
- 回答里写对的名字：拉丁字母的词、引号/书名号里的词、行情那种「智谱 426.20 港元」开头的名字。`Heard` 里已经有
  这三样的提取（`LATIN`、`QUOTED`、`QUOTE_NAME`、停用词表、`words()`、`standsAlone()`…），**复用它**：需要的话把
  `Heard.java` 里的 private 改成包内可见（只许改可见性，不许改行为；`HeardChecks` 必须照旧全绿）。
- 一个名字要**被用户用到**才进词表：这一回合用户的话里有它（去掉空格、不分大小写后相同），或者有一个词按下面的
  规则被认作它。只在回答里出现的名字（回答提到的别人、别的公司）不进词表。
- 名字「用到的次数」= 用户提到它的回合数，**包括事后才认领的回合**：三次没听懂的 `TABLE` 在「TI BO 这个人」认出
  Tibo 以后，都算用户提到了 Tibo（所以 Tibo 是 4 次，不是 1 次）。`hints` 里「用过至少两次」看的就是这个数。
- 名字的标准写法取回答里的写法（`names` 里有就用它）；同一个名字大小写不同的几种写法是同一个名字。

**一个词怎么被认作某个名字的另一种写法**——分两档，别混：
- 严格档（任何时候都能用，包括 `hints` 在请求时对「出现过至少两次的名字」做的模糊匹配）：
  - 拉丁：是长名字（≥5 个字母）的开头或结尾一截（`MAX`/`MINIMAX`，`OPENA`/`OPENAI`）；或者编辑距离 1
    （名字 ≥4 个字母；`TIBA`/`TIBO`，`ANTROPIC`/`ANTHROPIC`）。数字位不同不算（`HDMI1`≠`HDMI2`，Heard 里有这条）。
  - 中文对中文：字数相同、每个字主读音相同（`Pinyin.sameMainSound`，`质朴`/`智谱`）。
  - 中文对拉丁：这几个字的拼音连起来（不带声调）等于名字的字母（`提博` → tibo）。
  - 拆开念：`T I B O`、`TI BO`、`MINI MAX` 去掉空格后就是名字本身 → 给一个提示，告诉模型标准写法。
- 宽松档（**只在有对话证据时**用来学习，绝不用在 `hints` 的请求时匹配上）：
  - 拉丁：首字母相同，而且辅音骨架一个是另一个的前缀或相同（`TABLE`→t-b-l，`TIBO`→t-b；`CLOUD`/`CLAUDE` 都是 c-l-d）。
  - 中文：字数相同，每一对字要么主读音相同、要么韵母相同，且至少一对主读音相同（`制储` zhi-chu / `智谱` zhi-pu）。
  「对话证据」是下面两种：

**从返工里学**（这是这一单的核心）：
- 同一回合：听懂了，用户的话里有一个站得住的词 W（在名字的位置上，见 `Heard.standsAlone` 那套），回答/`names` 里
  的名字 N 和它宽松档对得上、而 N 本身不在用户的话里 → 记下 W 是 N 的一种写法（「查询制储的股价」→ 智谱的行情）。
- 跨回合：前面 `REPAIR_WINDOW_MS`（3 分钟）以内有没听懂的回合留下没着落的词 W，这一回合认出了名字 N，W 和 N
  宽松档对得上 → 记下 W 是 N 的写法（三次 `TABLE` 之后的「TI BO 这个人」）。对不上就不连（中间隔着一句天气、
  下一句认出的是首字母都不同的名字，都不连）；超过 3 分钟不连。
- 纠正：这一回合以「我说的是 / 我是说 / 我要的是 / 不是…是…」开头，而上一回合（3 分钟内）是**答了但答错了**的，
  上一回合话里的词 W 和这一回合认出的名字 N 严格档或宽松档对得上 → W 是 N 的写法；上一回合因为 W 而记下的名字
  （把 `MAX` 自己当成了一个名字）要撤掉。（11-07 12:20「查询MAX最新的股价」答成 MediaAlpha，接着「我说的是MINI MAX」。）

**`hints`** 里「写对了」的意思是：去掉大小写差别后和标准写法一样（`TIBO`、`tibo` 对 `Tibo` 都算写对，不提示）；
只差空格（`TI BO`、`T I B O`、`MINI MAX`）算拆开念，要提示。

**`hints`**：先看学过的写法（去空格、不分大小写后完全相同；词要站得住，`table tennis` 连成一个词以后不是 `table`），
再看拆开念的，再对「用过至少两次的名字」做严格档匹配。名字写对了不提示；`FORGET_AFTER_MS` 没用过的名字不提示。
最多 `MAX_HINTS` 条。`Heard.Hint` 的 `when` 填这个名字最近一次用到是哪天（「11月6日」这种写法，或「刚才」）。
`line()` 给模型看，一行，例如：`「TABLE」你以前说的是「Tibo」（听错过 3 次）；「提博」读起来像你常提到的「Tibo」`。

**`lines`**（给「关于用户」）：最多两行、合计不超过 160 字，按用到的次数排（次数相同看最近），最多 `MAX_LINE_NAMES`
个名字；只列名字，不列错写法。例如：`常提到的名字：MiniMax、Tibo、OpenAI、智谱（语音常把它们写成别的样子，听着像就按这些理解）`。

**上限和遗忘**：`MAX_NAMES` 个名字（满了先丢最久没用到的）、每个名字 `MAX_HEARD` 种写法（丢最少见的）、
`FORGET_AFTER_MS` 没用到的名字在 `learn` 时清掉。一个回合只学一次（按 `Turn.at`）。像密码的东西不进词表
（`Memory` 里那条规则：含「密码/口令/验证码/银行卡/卡号/身份证」或 6 位以上数字）。任何输入都不许抛异常
（null、空、坏掉的 JSON 结构：当成空词表重新开始）。
